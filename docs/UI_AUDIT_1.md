# UI layout audit 1 (Phase 10-A) · 2026-11-02

Layout only (plan §13): how pages look and read, not what they do. Every page was captured with `npm run ui:screens`
(phone 375 px, tablet 768 px, desktop 1280 px; light and dark; signed out and as a super admin; sample data: 2 minutes,
3 events, 6 members; encryption, donations, email and social keys not set up). 33 pages, 198 screenshots. Three reviewers
scored the pages against the checklist in plan §13.3 and traced each problem to the code; the serious ones were re-checked.

**Severity.** High: confuses or blocks a beginner, looks broken, shows developer text to the public, fails contrast, or
breaks on a phone. Medium: inconsistent, unpolished, jargon, missing guidance. Low: polish.

**Totals.** About 100 separate problems, merged here into 8 bugs (§1) and 53 layout rows (§2–§5): 17 High, 30 Medium,
6 Low. The bugs are not layout; they are listed first because visitors see them, and fixing them inside Phase 10 needs the
owner's approval because they change behaviour.

## 6. Strengths to keep

- Colour tokens for light and dark in `app/globals.css`; token-based pages (dashboard, Members, Calling, Security, Encryption, Action Items) already look finished in both themes.
- Visible keyboard focus everywhere (`:focus-visible` ring), skip link, `aria-current` in both navs, a working Ctrl/⌘ K jump dialog.
- Shared admin pieces (`AdminPageHeader`, `AdminSectionCard`, `AdminKpiCard`, `AdminActionCard`, `EmptyState`) and skeletons in the encryption gate: the dashboard is the template for the rest.
- Plain, honest copy in many places: admin sign-in steps, consent wording on Members, the Donate page's story ("Why the Gumba Project Matters", "A Message to Our Donors"), public minutes headings.
- Strong safety steps in the encryption flows (named devices, code comparison with a required tick, recovery key typed back, confirm before destructive actions): restyle, don't remove.

## 7. Upgrade 1 plan (10-B), in order

1. **Approve and fix the bugs in §1** (behaviour changes; owner decision): event dates, edit-event load/delete, real GoFundMe link (owner supplies it), remove placeholder media and the public onboarding/doc-generator links, hide the sample-threads button, fix the calling-tree status line.
2. **Shared foundations**: type scale, two radii, ban `text-white` on primary, replace raw palette colours with tokens, `Tabs`/`Select` components, sidebar at `lg`, account menu in the top bar, one admin content width, wrapping button rows.
3. **Public site as the organisation's own**: new header menu, themed footer, rebuilt home (photo hero, About, events, Gumba strip, Follow us), Donate restructure, events pages, 404, verify, sign-in pages.
4. **Admin pages onto the shared frame**, worst first: Meeting Minutes, Events, Document generator, Calling Tree/Campaigns/My Calls guidance, Encryption and Security wording (every step kept), dashboard activity text, Plans & Issues, Chat, Members, Broadcasts, Gallery, GUMBA.
5. Re-run `npm run ui:screens`, the full test suite and an axe check, then Audit 2.
